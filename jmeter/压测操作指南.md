# FlashSale 压测操作指南

## 1. 启动依赖

```powershell
redis-server
docker compose up -d          # RabbitMQ；或本地启动 rabbitmq-server
$env:MYSQL_PASSWORD = "你的密码"
cd FlashSaleBackend
.\mvnw.cmd spring-boot:run
```

确认日志出现 `Started FlashSaleBackendApplication`，且 Redis 中 `seckill:stock:1` 为 `100`。

## 2. 准备测试数据

```powershell
mysql -uroot -p -D flashsale < ..\jmeter\prepare.sql
```

如需 500 个账号参与压测，把 `users.csv` 扩充为：

```csv
13800000001,123456
13800000002,123456
13800000003,123456
...
```

## 3. 选择档位

| 档位 | 线程 | ramp-up | 时长 | 用途 |
| --- | --- | --- | --- | --- |
| light | 50 | 5s | 30s | 冒烟 |
| medium | 200 | 10s | 60s | 默认推荐 |
| heavy | 500 | 10s | 120s | 找瓶颈 |
| custom | 任意 | 任意 | 任意 | 手工输入 |

```powershell
.\run-test.ps1 -Mode medium
```

脚本会替换占位符、修正 CSV 绝对路径，再调用 JMeter。JMeter 路径优先读环境变量 `JMETER_HOME`（如 `D:\jmeter\apache-jmeter-5.6.3`），未设置时使用该默认值。

## 4. 结果解读

- `POST /api/seckill/1`：秒杀主请求，业务失败也会是 HTTP 200，需要看 JMeter 响应体里的 `code`
- `GET /api/order/result/1`：轮询请求，正常返回 `orderId=-1` 或订单号
- HTML 报告位于 `results/report-*/index.html`

## 5. 一致性校验

```sql
USE flashsale;

SELECT g.id, g.stock_count, COUNT(o.id) AS orders,
       CASE WHEN g.stock_count >= COUNT(o.id) THEN 'OK' ELSE 'OVERSELL' END AS result
FROM goods g LEFT JOIN order_info o ON o.goods_id = g.id
WHERE g.id = 1 GROUP BY g.id, g.stock_count;

SELECT COUNT(*) FROM (
  SELECT user_id, goods_id FROM seckill_order
  GROUP BY user_id, goods_id HAVING COUNT(*) > 1
) t;
```

```powershell
redis-cli GET seckill:stock:1
```

## 6. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 大量 `500102` | Token 未写入全局属性 | 确认登录线程组先执行、BeanShell 未报错 |
| 大量 `500206` | 单用户 5 秒内超过 5 次 | 增加用户池，或降低单线程频率 |
| 全部 `500203` | 库存已售罄 | 重置 Redis 与数据库后重启后端 |
| 报告无数据 | JMeter 路径错误 | 修改 `$jmeterHome` |
| `simulate.ps1` 数字很好看 | 那是模拟数据 | 不要作为性能结论 |
